## 01 · SaaS 랜딩 페이지와 재사용 UI

첫 방문자가 제품 가치와 다음 행동을 이해하는 반응형 랜딩을 만든다.

**모호한 요청:** 세련되고 트렌디한 랜딩 페이지를 만들어 줘.

### 구체적인 제작 명령

```text
소규모 팀의 프로젝트 관리 서비스를 소개하는 랜딩 페이지를 구현하라. 첫 화면에서 ‘마감과 담당자를 한곳에서 확인한다’는 가치와 무료 체험 CTA 하나를 강조하라.
데스크톱은 12열 그리드, 최대 본문 폭 1200px, 카드 간 24px를 시작값으로 사용하라. 모바일은 1열로 바꾸고 320px에서도 긴 제목·버튼이 넘치지 않게 하라.
색·간격·타입·반경을 의미 기반 토큰으로 정의하고 Button·FeatureCard 변형을 재사용하라. 본문·버튼·포커스의 대비와 시맨틱 HTML을 확인하라.
제품 스크린샷은 목적에 맞는 반응형 이미지로 제공하고 너비·높이를 예약하라. CTA의 실제 목적지와 성공·실패 상태를 명시하라. 저장소의 기존 스택을 유지하고 실제 실행·빌드 결과를 보고하라.
```

### 산출물과 작업 명세

| 항목 | 명세 |
| --- | --- |
| 범위 | 헤더·히어로·핵심 기능 3개·요금 요약·FAQ·푸터 |
| 화면 | 320/768/1280px에서 내용과 행동 확인; 숫자는 이 사례의 검수 너비 |
| 동작 | CTA 목적지, 메뉴·FAQ 키보드 조작, 포커스 표시 |
| 납품 | 실행 가능한 프로젝트·토큰 목록·자산 목록·검증 결과 |

### 결과가 틀렸을 때

| 관찰한 문제 | 원인 후보 | 수정 명령 |
| --- | --- | --- |
| 모든 버튼이 강하게 보인다 | 위계와 기본 행동이 불명확 | 체험 CTA만 primary로 두고 보조 이동은 secondary·링크로 내려라. |
| 긴 제목에서 카드 높이가 깨진다 | 고정 높이·좌표 배치 | 내용 기반 레이아웃과 최소 크기·줄바꿈을 적용하라. |
| 모바일이 느리고 흔들린다 | 큰 이미지와 공간 미예약 | 적절한 srcset·sizes 및 이미지 비율 예약을 적용하라. |

### 완료 판정

- 5초 안에 제품 목적·기본 행동을 찾는다.
- 키보드로 핵심 과업을 수행한다.
- 중간 너비·확대에서 가로 넘침이 없다.
- 실제 파일·명령·실행 결과가 기록된다.

<a name="case-02"></a>
## 02 · 다국어 디자인 시스템

긴 한글·영문·숫자가 공존해도 유지되는 UI 규칙을 만든다.

**모호한 요청:** 우리 회사에 맞는 디자인 시스템을 만들어 줘.

### 구체적인 제작 명령

```text
업무용 대시보드의 색·타입·간격·반경 토큰과 Button·Input·Alert·Card를 정의하라. 원시 색상과 action.primary 같은 의미 토큰을 구분하고 light/dark 테마를 연결하라.
컴포넌트마다 size·intent·state의 유효 조합을 표로 제공하라. loading·disabled·error를 색만으로 구분하지 말고 텍스트·역할·포커스 규칙을 포함하라.
한글과 영문 제목, 긴 독일어 버튼 라벨에 대응하도록 오토 레이아웃·최소 폭·줄바꿈을 정하라. 본문 폰트와 폴백·글리프 지원을 확인하라.
토큰은 합의한 JSON 구조와 CSS 변수로 출력하고 이름·단위·별칭 해석을 문서화하라. 모든 변형의 실제 렌더와 키보드 검수 결과를 제출하라.
```

### 산출물과 작업 명세

| 항목 | 명세 |
| --- | --- |
| 토큰 | 원시 값·의미 별칭·컴포넌트 연결의 세 층을 구별 |
| 변형 | 상태·크기·강조의 유효 조합과 기본값 |
| 언어 | 한글·영문·긴 라벨·통화·누락 글리프 |
| 납품 | 토큰 파일·컴포넌트 예제·변형 행렬·사용 규칙 |

### 결과가 틀렸을 때

| 관찰한 문제 | 원인 후보 | 수정 명령 |
| --- | --- | --- |
| 다크 테마에서 글자가 사라진다 | 원시 색 하드코딩·배경 조합 미검토 | 의미 토큰으로 연결하고 각 상태의 실제 전경·배경을 검사하라. |
| 로딩 버튼이 옆으로 움직인다 | 내용에 따라 너비 급변 | 기준 너비를 유지하고 상태 텍스트·스피너 영역을 예약하라. |
| 변형이 수백 개로 불어난다 | 독립 속성과 불가능한 조합 미정의 | 사용 사례별 유효 조합만 남기고 중복 변형을 통합하라. |

### 완료 판정

- 의미 토큰 하나의 변경이 관련 요소에 반영된다.
- 긴 라벨과 200% 확대에 내용 손실이 없다.
- 기본·오류·포커스 상태를 구분할 수 있다.
- 실제 사용 가능한 데이터·코드 예제가 있다.

## 03 · 인쇄 브로슈어와 디지털 PDF

화면 열람본과 인쇄 제출본의 서로 다른 조건을 명확히 한다.

**모호한 요청:** 고급스러운 소개서를 PDF로 만들어 줘.

### 구체적인 제작 명령

```text
제품 소개 브로슈어를 12쪽으로 편집하라. 제목·본문·캡션의 타입 스케일과 기준선 리듬을 만들고, 제목이 페이지 끝에 홀로 남지 않도록 조판하라.
디지털 열람본은 검색 가능한 텍스트·목차 링크·글꼴 임베딩을 유지하라. 인쇄 제출본은 인쇄소가 확정한 완성 크기·프로파일·bleed·PDF 조건을 적용하라. 미확정 규격은 임의 인증으로 대체하지 말고 목록으로 표시하라.
사진은 실제 배치 크기의 유효 PPI를 검사하고 작은 검정 글자·별색·흰색 오버프린트를 확인하라. 모든 최종 페이지를 렌더링해 글자 누락·표 분할·넘침을 검수하라.
```

### 산출물과 작업 명세

| 항목 | 명세 |
| --- | --- |
| 디지털 | 선택·검색 가능한 텍스트, 링크, 임베딩된 폰트 |
| 인쇄 | 인쇄소 확인 후 프로파일·재단·별색·출력 규격 적용 |
| 이미지 | 원본 픽셀과 실제 배치 크기의 관계를 계산 |
| 납품 | 편집 원본·디지털 PDF·필요 시 별도 인쇄 PDF·프리플라이트 결과 |

### 결과가 틀렸을 때

| 관찰한 문제 | 원인 후보 | 수정 명령 |
| --- | --- | --- |
| 흰 테두리가 인쇄에 생긴다 | 배경이 재단선에서 끝남 | bleed 끝까지 배경을 확장하고 인쇄소 요구량을 확인하라. |
| 특정 글자가 네모로 나온다 | 미지원 글리프·폰트 누락 | 지원 글꼴·폴백·임베딩을 점검하고 최종 PDF를 다시 렌더링하라. |
| 제목만 아래에 남는다 | keep 규칙 부재 | 제목과 뒤 본문을 함께 유지하고 해당 분할을 조정하라. |

### 완료 판정

- 모든 페이지의 글자·표가 정상이다.
- 검색·복사·목차 이동이 동작한다.
- 인쇄 규격은 확정된 요구와 일치한다.
- 교정본과 실제 납품본의 버전이 일치한다.

## 04 · 게임용 3D 소품

콘셉트 이미지와 실제 엔진 투입 자산을 별도로 정의한다.

**모호한 요청:** 멋진 저폴리 상자를 만들어 줘.

### 구체적인 제작 명령

```text
게임의 근접 관찰용 소형 보급 상자를 제작하라. 먼저 정면·측면·후면 참조에서 손잡이·경첩·라벨 위치를 일치시켜라. 렌더 이미지와 실제 메시 납품을 구별하라.
목표 엔진·단위·삼각형·재질·텍스처 예산을 확인한 후 실루엣과 여닫는 부분에 필요한 토폴로지를 배분하라. UV의 왜곡·패딩·텍셀 밀도를 점검하라.
고밀도 디테일이 있다면 low-poly로 normal·AO를 분리 베이크하고 맵의 색 해석과 normal Y 관례를 엔진에 맞춰라. 기본색에 조명을 굽지 마라.
편집 원본·교환 파일·맵·단위·통계·엔진 검수 화면을 제공하고 누락된 요구는 가정으로 표시하라.
```

### 산출물과 작업 명세

| 항목 | 명세 |
| --- | --- |
| 형태 | 각 방향의 치수 관계·개폐 축·비대칭 특징 |
| 메시 | 목표 엔진에 맞춘 단위·축·원점·삼각형화 |
| 맵 | base color·normal·roughness·metallic·필요 AO의 역할 분리 |
| 검수 | 실루엣·체커·조명 회전·엔진 임포트 |

### 결과가 틀렸을 때

| 관찰한 문제 | 원인 후보 | 수정 명령 |
| --- | --- | --- |
| 실루엣은 매끈한데 디테일만 삼각형이다 | low-poly를 표면 무늬로 해석 | 실제 메시 구조·통계를 확인하고 목적에 맞게 리토폴로지하라. |
| 요철이 반대로 보인다 | normal 관례·색 해석 오류 | Y 채널 관례와 비색 데이터 설정을 맞춰라. |
| 라벨만 흐리다 | UV 면적·텍셀 밀도 부족 | 중요 면의 UV 배분과 목표 텍셀 밀도를 조정하라. |

### 완료 판정

- 모든 방향의 부품 위치가 일치한다.
- 메시·재질·텍스처 예산을 기록한다.
- 외부 링크 없이 목표 환경에서 열린다.
- 원본에서 수정·재베이크가 가능하다.

<a name="case-05"></a>
## 05 · 제품 공개 영상

카메라 움직임·제품 일관성·실제 인코딩을 분리한다.

**모호한 요청:** 향수 광고를 영화처럼 4K로 만들어 줘.

### 구체적인 제작 명령

```text
동일 향수 참조 이미지를 기준으로 5초 제품 공개 샷을 만들어라. 카메라는 medium product shot에서 close-up으로 천천히 dolly in하고 병은 같은 위치·형태·라벨을 유지한다. 배경에는 자연스러운 이동 시차가 보이며 마지막은 짧게 정지한다.
The camera slowly dollies in toward the stationary bottle. Its shape and label remain consistent; reflections shift naturally and the background shows gentle parallax.
생성 모델이 제공하는 길이·비율을 실제 설정에서 선택하고, 정확한 5초·24fps 납품은 편집 타임라인에서 확인하라. 검토본과 고품질 마스터의 코덱을 별도로 지정하고 원본·업스케일·리타이밍 이력을 보고하라.
```

### 산출물과 작업 명세

| 항목 | 명세 |
| --- | --- |
| 구도 | 중앙 제품·전후 이동·고정된 제품 형태 |
| 타임라인 | 예시 5초·24fps·120프레임; 실제 파일 검사 |

| 마스터 | 수신 편집기와 합의한 중간 코덱·색공간·해상도 |

- 시작·중간·끝의 제품 특징이 일치한다.
- 프레임·코덱·해상도를 메타데이터로 확인한다.

## 06 · 브랜드 루프 모션

```text
로고 심벌 세 개가 고정된 중심 주변에서 작게 순환하는 4초 루프를 설계하라. 카메라·배경·전체 밝기는 고정하고 각 심벌의 형태와 색은 유지한다.
```

| 관찰한 문제 | 원인 후보 | 수정 명령 |
| --- | --- | --- |
| 타자를 치면 예전 결과가 돌아온다 | 응답 순서 경쟁 | 최신 요청 ID 확인 또는 취소를 적용하라. |
| 목록이 커질수록 SQL이 폭증한다 | ORM N+1 | 관련 데이터를 배치 조회하고 질의 수를 측정하라. |
| 수정 뒤 값이 안 바뀐다 | 캐시 무효화 누락 | 관련 상세·목록 키를 갱신하고 필터별 일관성을 확인하라. |

### 완료 판정

- URL 새로고침으로 같은 검색을 복원한다.
- 늦은 요청이 결과를 덮지 않는다.
- 페이지 경계에 누락·중복이 없다.
- 동일 조건의 측정으로 개선을 입증한다.

<a name="case-11"></a>
## 11 · 이미지 처리 작업 시스템

작업 수·자원·재시도·실패를 통제하는 비동기 파이프라인을 만든다.

**모호한 요청:** 파일을 올리면 AI가 자동으로 처리하는 서비스를 만들어 줘.

### 구체적인 제작 명령

```text
업로드·대기·처리·완료·실패·취소 상태를 명시한 작업 API를 설계하라. 파일 형식·크기·내용을 검증하고 사용자별 접근을 제한하라. 실제 비밀값은 서버에서 관리하라.
처리는 용량이 제한된 큐와 워커로 분리하고 외부 생성 API 동시성·전체 시간 예산·재시도 횟수를 설정하라. 작업 ID로 중복 처리를 제어하고 재전달·프로세스 종료 시 복구 정책을 정의하라.
원본·변환본·결과의 매니페스트를 남기고 상태 API에서 진행과 실패 원인을 제공하라. 로그·메트릭·trace를 작업 ID로 연결하되 개인정보와 비밀을 남기지 마라.
```

### 산출물과 작업 명세

| 항목 | 명세 |
| --- | --- |
| 상태 | 허용 전이·취소 후 동작·재시도 관계 |
| 자원 | 큐 용량·워커·동시 외부 호출·파일 제한 |
| 복구 | 중복·재전달·타임아웃·실패 큐·보존 기간 |
| 인계 | 원본·결과·모델·설정·작업 이력·권한 |

### 결과가 틀렸을 때

| 관찰한 문제 | 원인 후보 | 수정 명령 |
| --- | --- | --- |
| 요청이 많아 메모리가 터진다 | 무한 큐·무제한 병렬 호출 | bounded queue·동시성 상한·과부하 응답을 구현하라. |
| 같은 작업 결과가 여러 번 저장된다 | 재전달 멱등성 없음 | 작업 상태와 결과 저장을 원자적으로 처리하라. |
| 실패 원인을 찾을 수 없다 | 분산 신호 연결 없음 | 작업 ID·요청 ID를 경계마다 유지하고 오류 유형을 구조화하라. |

### 완료 판정

- 워커 종료 뒤 작업을 안전하게 재개한다.
- 과부하에서도 자원 상한이 유지된다.
- 취소된 작업의 늦은 결과 정책이 명확하다.
- 한 실패를 관련 로그·요청까지 추적한다.

<a name="case-12"></a>
## 12 · 브랜드 캠페인 통합 인계

하나의 제품·브랜드 규칙으로 디자인·영상·코드를 연결한다.

**모호한 요청:** 브랜드 캠페인을 이미지부터 웹까지 전부 만들어 줘.

### 구체적인 제작 명령

```text
제품의 실루엣·색·로고 위치·부품 수를 참조 시트로 확정하고 시안마다 유지할 특징과 변경 가능한 배경·조명을 구분하라. 브랜드 색·타이포·간격을 토큰으로 관리하라.
디자인은 가로 히어로·세로 광고·투명 컷아웃으로, 영상은 제품 공개 샷·루프·자막 버전으로, 웹은 반응형 랜딩과 실제 CTA 동작으로 제작하라. 각 도구에 필요한 입력과 후처리 책임을 분리하라.
공통 자산 ID·버전·매니페스트를 사용하고 모든 파생본이 승인된 원본에서 만들어졌는지 확인하라. 최종 인수 기준은 각 파일의 실제 속성과 웹의 동작으로 검증하라. 미검증 항목과 외부 의존성을 명시하라.
```

### 산출물과 작업 명세

| 항목 | 명세 |
| --- | --- |
| 공통 | 브랜드 토큰·제품 참조·고정 특징·자산 ID |
| 디자인 | 크롭별 구도·실제 알파·편집 원본 |
| 영상 | 형태 일관성·루프 경계·코덱·자막·음량 |
| 개발 | 반응형 자산·성능·접근성·실제 행동 |
| 인계 | 버전·출처·사용 조건·검수 결과·재생성 방법 |

### 결과가 틀렸을 때

| 관찰한 문제 | 원인 후보 | 수정 명령 |
| --- | --- | --- |
| 영상에서 제품 버튼 수가 바뀐다 | 참조 특징이 문서화되지 않음 | 버튼 수·위치·실루엣을 고정 목록으로 만들고 샷별 비교하라. |
| 웹에 오래된 시안이 보인다 | 파생본 버전·캐시 혼선 | 매니페스트로 승인 버전과 파일 해시·배포 참조를 대조하라. |
| 모든 결과가 있지만 재수정이 어렵다 | 원본·의존성 누락 | 편집 원본·폰트·연결 자산·실행 설정을 수집하고 재출력을 검증하라. |

### 완료 판정

- 세 분야의 제품·브랜드 특징이 일치한다.
- 승인본과 배포본의 연결을 확인한다.
- 각 자산은 명세대로 열리고 동작한다.
- 다른 담당자가 원본에서 파생본을 만들 수 있다.
