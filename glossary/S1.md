<a name="s1-01"></a>
## S1-01 · 상태 관리

**State Management** · PDF 95쪽

### 뜻·쓰임

앱의 현재 데이터와 그 변화 규칙을 관리하는 설계다. 로컬 UI 상태, 공유 클라이언트 상태, URL 상태, 서버 상태는 수명과 소유자가 다르다. 계산 가능한 값을 중복 저장하면 서로 어긋날 위험이 커진다.

### 혼동 구분

UI 상태·서버 상태·URL 상태는 소유자와 수명이 다르다. 계산 가능한 파생값을 중복 저장하지 않는다.

### 실행 명령

```text
장바구니의 UI 상태와 서버 데이터를 분리해 설계하라. 합계는 상품 목록에서 계산하고 로딩·실패·재시도 상태와 전이표를 제시하라.
```

### 설정·계약

먼저 상태의 소유자와 갱신 이벤트를 정한다. 전역 저장소 도입 자체를 목표로 삼지 않는다. 비동기 응답의 도착 순서, 캐시 무효화, 낙관적 갱신 실패 시 복구를 함께 명세한다.

### 검수

연속 클릭·느린 응답·화면 재진입에서도 가격과 수량이 일치하는지 확인.

### 수정 명령

```text
목록과 합계가 어긋나면 합계 상태를 없애고 단일 데이터에서 계산하라.
```

<a name="s1-02"></a>
## S1-02 · 반응형 중단점

**Responsive Breakpoint** · PDF 95쪽

### 뜻·쓰임

화면 또는 컨테이너의 조건에 따라 레이아웃 규칙이 달라지는 경계다. 특정 기기 이름보다 콘텐츠가 더 이상 읽히거나 배치되지 않는 너비를 기준으로 잡는 편이 실용적이다.

### 혼동 구분

Breakpoint는 콘텐츠가 배치 방식을 바꾸는 경계다. 특정 휴대폰 모델에만 맞추는 값이 아니다.

### 실행 명령

```text
모바일 우선 CSS를 작성하라. 48rem에서 2열, 64rem에서 3열로 전환하고, 320px부터 긴 제목과 키보드 확대에 따른 넘침을 점검하라.
```

### 설정·계약

48/64rem은 예시이며 브라우저 기본값·사용자 설정에 따라 px 환산이 달라진다. viewport media query와 container query를 구별한다. min-width 기준을 일관되게 써 경계에서 규칙 충돌을 줄인다.

### 검수

경계 직전·정확한 경계·직후 너비, 200% 확대와 가로 스크롤을 확인.

### 수정 명령

```text
경계 사이 너비에서 넘침이 생기면 최소 콘텐츠 폭과 줄바꿈을 다시 정하라.
```

<a name="s1-03"></a>
## S1-03 · 컴포넌트

**Component** · PDF 96쪽

### 뜻·쓰임

입력·출력·UI·행동의 경계가 있는 재사용 가능한 화면 단위다. 카드·입력·페이지 구조를 나눌 때 쓰며 책임과 변경 이유를 기준으로 분리한다.

### 혼동 구분

디자인 툴의 컴포넌트와 코드 컴포넌트는 대응할 수 있지만 자동으로 동일 구조가 되지는 않는다.

### 실행 명령

```text
상품 카드를 props 기반 컴포넌트로 분리하고 가격·품절·이미지 오류를 입력으로 받게 하라. 데이터 조회는 상위 계층에서 처리하라.
```

### 설정·계약

공개 props·이벤트·기본값·접근성 이름을 명시한다. 아주 작은 요소를 무조건 별도 파일로 만들지는 않는다.

### 검수

다른 데이터·상태에서도 같은 구조가 동작하고 변경이 관계없는 화면에 영향을 주지 않는지 확인.

### 수정 명령

```text
복제된 카드 세 개를 수정하기보다 공통 컴포넌트와 차이 속성으로 통합하라.
```

<a name="s1-04"></a>
## S1-04 · 제어·비제어 입력

**Controlled / Uncontrolled Input** · PDF 96쪽

### 뜻·쓰임

입력값을 앱 상태가 관리하는지, DOM의 내부 값이 중심인지 구별하는 방식이다. 폼 구현에서 초기값·검증·리셋의 일관성을 결정한다.

### 혼동 구분

React의 value와 defaultValue는 같은 역할이 아니다. 방식이 실행 중 바뀌면 경고와 값 유실이 생길 수 있다.

### 실행 명령

```text
회원정보 폼은 명시적 상태로 입력을 제어하고 비동기 초기값을 받은 뒤 사용자가 수정한 값을 덮지 않게 하라.
```

### 설정·계약

초기값·빈 문자열/null·서버 재조회·리셋·제출 정책을 정한다. 라이브러리의 폼 관리 방식을 존중한다.

### 검수

입력·자동완성·초기 데이터 지연·리셋에서 값이 일관적인지 확인.

### 수정 명령

```text
모든 재렌더마다 서버 값을 다시 넣지 말고 최초 로드와 사용자 편집 상태를 구별하라.
```

<a name="s1-05"></a>
## S1-05 · 라우팅

**Routing** · PDF 97쪽

### 뜻·쓰임

URL이나 탐색 상태를 화면·처리와 연결하는 규칙이다. 페이지 이동·직접 링크·뒤로 가기·권한 경계를 설계할 때 필요하다.

### 혼동 구분

화면을 조건부로 숨기는 것만으로 URL 계약이 완성되지는 않는다. 서버 라우팅과 클라이언트 라우팅의 역할을 구분한다.

### 실행 명령

```text
/products와 /products/{id}를 연결하고 필터는 쿼리 문자열에 보존하라. 직접 진입·새로고침·404·로그인 후 복귀를 처리하라.
```

### 설정·계약

경로 변수·쿼리·중첩 레이아웃·데이터 로딩·인코딩 규칙을 정한다.

### 검수

뒤로 가기와 공유 링크에서 같은 화면 상태가 복원되고 잘못된 ID가 처리되는지 확인.

### 수정 명령

```text
메뉴 클릭만 검사하지 말고 상세 URL을 새 탭에서 직접 열어라.
```

<a name="s1-06"></a>
## S1-06 · 클라이언트·서버 렌더링

**CSR / SSR** · PDF 97쪽

### 뜻·쓰임

CSR은 주로 브라우저에서 화면을 만들고 SSR은 서버에서 HTML을 생성해 전달하는 방식이다. 초기 표시·검색 노출·서버 비용·상호작용의 균형을 정할 때 쓴다.

### 혼동 구분

SSR이 모든 데이터를 공개해도 된다는 뜻은 아니다. SSG는 빌드 등 사전 시점의 정적 생성으로 별도 구분한다.

### 실행 명령

```text
공개 상품 설명은 서버에서 렌더링하고 사용자 장바구니는 인증된 데이터로 분리하라. 초기 HTML과 클라이언트 동작을 모두 검사하라.
```

### 설정·계약

캐시·개인화·데이터 갱신 시점·로딩 경계를 정한다. 프레임워크의 실제 기능에 맞춰 구현한다.

### 검수

느린 연결에서 첫 화면이 의미 있고 사용자 데이터가 다른 사람에게 캐시되지 않는지 확인.

### 수정 명령

```text
‘SSR로 빠르게’라는 말 대신 서버에서 필요한 내용과 클라이언트에서 필요한 상호작용을 나눠라.
```

<a name="s1-07"></a>
## S1-07 · 하이드레이션

**Hydration** · PDF 98쪽

### 뜻·쓰임

서버가 만든 HTML에 클라이언트의 상호작용과 상태를 연결하는 과정이다. SSR 기반 앱의 초기 표시 이후 동작을 완성한다.

### 혼동 구분

서버와 브라우저의 첫 렌더 결과가 다르면 mismatch가 발생할 수 있다. 모든 프레임워크의 처리 방식이 같지는 않다.

### 실행 명령

```text
서버와 클라이언트의 초기 출력에서 날짜·랜덤 값·브라우저 전용 조건이 불일치하지 않게 하고 hydration 경고를 해결하라.
```

### 설정·계약

안정적인 초기 데이터와 ID를 사용한다. 브라우저 API는 적절한 클라이언트 경계에서 접근한다.

### 검수

콘솔 경고·초기 깜빡임·버튼 무반응과 서버 내용 교체가 없는지 확인.

### 수정 명령

```text
경고를 숨기는 옵션부터 쓰지 말고 최초 출력이 달라지는 값을 찾아 정리하라.
```

## S1-08 · 플렉스박스·CSS 그리드

**Flexbox / CSS Grid** · PDF 98쪽

### 뜻·쓰임

Flexbox는 한 축의 정렬·분배, Grid는 행과 열의 배치 관계에 강한 CSS 레이아웃 도구다. 실제 화면 구조를 규칙으로 구현할 때 쓴다.

### 혼동 구분

둘 중 하나만 써야 하는 것은 아니다. Grid의 열과 카드 내부 Flex를 조합할 수 있다.

### 실행 명령

```text
목록은 CSS Grid로 반복 열을 구성하고 카드 내부 버튼 행은 Flexbox로 정렬하라. 긴 제목에서도 최소 폭과 넘침을 처리하라.
```

### 설정·계약

gap·minmax·flex-basis·min-width·wrap을 지정한다. 고정 높이와 absolute로 구조 문제를 덮지 않는다.

### 검수

중간 너비·긴 텍스트·빈 아이콘에서도 정렬과 읽기 순서가 유지되는지 확인.

### 수정 명령

```text
카드를 좌표로 배치하지 말고 흐름 기반 레이아웃으로 바꿔라.
```

## S1-09 · 스태킹 컨텍스트

**Stacking Context / z-index** · PDF 99쪽

### 뜻·쓰임

겹치는 요소가 어떤 그룹과 순서로 쌓이는지 결정하는 체계다. 모달·드롭다운·고정 헤더의 가림 문제를 해결할 때 쓴다.

### 혼동 구분

z-index를 크게 한다고 모든 조상 경계를 넘는 것은 아니다. transform·opacity 등은 새 컨텍스트를 만들 수 있다.

### 실행 명령

```text
드롭다운이 카드 뒤에 가려지는 원인을 조상 stacking context와 overflow에서 찾고, 필요한 오버레이는 적절한 최상위 레이어에 배치하라.
```

### 설정·계약

레이어 역할별 z-index 토큰·portal·클리핑·포커스 관리를 정한다. 시각 순서와 DOM 접근성 순서를 함께 본다.

### 검수

모달·헤더·툴팁이 동시에 떠도 가림과 클릭 대상이 올바른지 확인.

### 수정 명령

```text
999999를 추가하지 말고 컨텍스트를 만드는 조상과 클리핑 규칙을 수정하라.
```

<a name="s1-10"></a>
## S1-10 · 반응형 이미지

**Responsive Images** · PDF 99쪽

### 뜻·쓰임

화면 크기·픽셀 밀도·구도에 맞는 이미지 자원을 선택해 제공하는 방식이다. 성능과 선명도, 모바일 크롭을 동시에 관리한다.

### 혼동 구분

CSS로 큰 이미지를 작게 보여 주는 것과 다르다. 해상도 전환과 art direction은 서로 다른 목적이다.

### 실행 명령

```text
srcset과 sizes로 적절한 해상도를 제공하고 모바일에는 제목 공간을 확보한 별도 crop을 picture로 연결하라. 너비·높이도 예약하라.
```

### 설정·계약

후보 이미지의 실제 픽셀 수·sizes의 레이아웃 조건·포맷·alt를 지정한다.

### 검수

네트워크에서 선택된 파일 크기와 화면 크롭·레이아웃 이동·시각 품질을 확인.

### 수정 명령

```text
원본 4K를 모든 화면에 보내지 말고 필요한 후보와 실제 표시 폭을 맞춰라.
```
