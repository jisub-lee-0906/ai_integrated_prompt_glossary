> 글자의 형태·간격·줄 흐름을 어떤 값으로 지시할 것인가?

타이포 수정은 글자 크기 하나로 해결되지 않는다. 서체, 특정 쌍의 간격, 전체 자간, 행간, 문단 길이를 나눠 지시한다. 최종 사용 크기와 다른 뷰어에서의 글꼴 표시를 함께 확인한다.

**작업 순서:** 서체 선택 → 크기 계층 → 자간·행간 → 줄바꿈 → 글꼴 납품

<a name="d3-01"></a>
## D3-01 · 서체와 폰트

**Typeface / Font** · PDF 23쪽

### 뜻·쓰임

서체는 디자인 계열을, 폰트는 그 계열의 구체적 스타일·파일을 가리키는 문맥이 많다. 제품에서는 패밀리·굵기·스타일·지원 문자를 함께 지정해야 결과가 재현된다.

### 혼동 구분

serif/sans-serif 같은 분류만으로 특정 서체가 결정되지 않는다. 같은 이름이어도 파일 버전과 글리프 범위가 다를 수 있다.

### 실행 명령

```text
한글·영문 혼합 본문용 서체를 선택하고 family, Regular/Bold 파일, 숫자 폭, 대체 글꼴과 사용 허가 확인 항목을 명시하라.
```

### 설정·계약

본문 크기·표시 매체·지원 언어를 먼저 준다. 합성 볼드 대신 실제 굵기 파일을 우선하고 특수문자 누락을 점검한다.

### 검수

한글 받침·영문·숫자·통화 기호가 정상 렌더링되고 다른 환경에서도 줄바꿈이 유지되는지 확인.

### 수정 명령

```text
폰트 이름만 전달하지 말고 정확한 파일과 사용한 굵기·버전을 함께 기록하라.
```

<a name="d3-02"></a>
## D3-02 · 커닝

**Kerning** · PDF 23쪽

### 뜻·쓰임

특정 글자 쌍 사이의 시각적 간격을 조정하는 작업이다. 로고나 큰 영문 제목에서 AV·To 같은 쌍의 빈틈을 보정할 때 효과적이다.

### 혼동 구분

Tracking은 글자열 전체 간격, Kerning은 특정 쌍의 간격이다. 전체 자간으로 개별 쌍의 문제를 고치면 다른 곳이 벌어진다.

### 실행 명령

```text
영문 워드마크의 전체 자간은 유지하고 AV와 To 쌍의 광학적 빈틈만 조정하라. 수정 전후를 같은 크기로 비교하라.
```

### 설정·계약

먼저 글꼴의 kerning을 적용하고 필요한 쌍만 미세 조정한다. 실제 사용 크기와 축소 버전에서 모두 판단한다.

### 검수

글자들이 일정한 리듬으로 읽히고 일부 쌍이 붙거나 단어가 분리되어 보이지 않는지 확인.

### 수정 명령

```text
제목 전체를 압축하지 말고 문제 글자 쌍을 지정해 간격을 보정하라.
```

<a name="d3-03"></a>
## D3-03 · 트래킹·자간

**Tracking / Letter Spacing** · PDF 24쪽

### 뜻·쓰임

선택한 글자열의 전반적인 간격을 조정하는 값이다. 작은 대문자 라벨·헤드라인의 밀도와 인상을 정할 때 쓰며 CSS에서는 letter-spacing으로 표현한다.

### 혼동 구분

카메라 Tracking Shot과 다른 분야의 동음 용어다. 커닝과 달리 전체 간격에 영향을 주며 한글은 과한 음수 자간에 민감하다.

### 실행 명령

```text
영문 대문자 라벨에 letter-spacing 0.06em을 적용하고 한글 본문은 기본 자간으로 유지하라. 좁은 카드에서 줄바꿈을 검사하라.
```

### 설정·계약

0.06em은 예시다. em은 글자 크기에 비례하므로 px와 섞어 생각하지 않는다. 사용자 자간 변경 시 콘텐츠가 잘리지 않게 한다.

### 검수

축소 화면에서 글자 식별성과 줄 길이가 유지되고 음수 자간으로 받침이 뭉치지 않는지 확인.

### 수정 명령

```text
넘치는 제목을 음수 자간만으로 맞추지 말고 폭·크기·줄 수를 함께 조정하라.
```

<a name="d3-04"></a>
## D3-04 · 리딩·행간

**Leading / Line Height** · PDF 24쪽

### 뜻·쓰임

줄과 줄 사이의 수직 리듬을 결정하는 값이다. 인쇄의 leading과 CSS line-height는 관련되지만 CSS는 행 상자의 높이를 조절한다.

### 혼동 구분

글자 사이 간격이나 문단 사이 간격과 다르다. 폰트 크기만 같아도 서체의 메트릭 때문에 보이는 행간이 달라질 수 있다.

### 실행 명령

```text
한글 본문 16px에 line-height 1.65를 출발점으로 적용하고 각주·표는 별도 규칙을 두라. 두 줄 이상의 실제 문장으로 검수하라.
```

### 설정·계약

단위 없는 비율은 상속 시 유리한 경우가 많다. 수식·인라인 아이콘·다른 글꼴이 끼어들 때 행 높이 변화도 확인한다.

### 검수

긴 본문에서 다음 줄을 쉽게 찾고 윗줄의 받침과 아랫줄 글자가 충돌하지 않는지 확인.

### 수정 명령

```text
문단 사이가 답답하면 행간과 문단 후 간격을 분리해 조절하라.
```

<a name="d3-05"></a>
## D3-05 · 타입 스케일

**Type Scale** · PDF 25쪽

### 뜻·쓰임

제목·본문·보조 정보의 크기를 관계 있는 단계로 정의하는 체계다. 화면 위계와 여러 페이지의 일관성을 만드는 데 쓴다.

### 혼동 구분

수학적 비율을 그대로 적용하는 것보다 역할별 가독성이 우선이다. 글자 크기와 HTML 제목 수준은 동일 개념이 아니다.

### 실행 명령

```text
본문 16px 기준 14/16/20/25/32px 타입 스케일을 만들고 페이지 제목·섹션 제목·라벨·보조 문구 역할에 연결하라.
```

### 설정·계약

예시 수열을 실제 콘텐츠로 조정한다. 모바일 제목은 유동 크기를 쓰더라도 최소·최대값과 줄 수를 정한다.

### 검수

각 역할이 구별되면서 긴 제목도 자연스럽게 줄바꿈되고 작은 정보가 지나치게 작지 않은지 확인.

### 수정 명령

```text
새 크기를 계속 추가하기 전에 기존 역할과 스케일에 수용 가능한지 검토하라.
```

<a name="d3-06"></a>
## D3-06 · 행 길이

**Measure / Line Length** · PDF 25쪽

### 뜻·쓰임

한 줄에 배치되는 글자열의 길이다. 긴 본문에서 너무 길면 다음 줄을 찾기 어렵고 너무 짧으면 시선 이동이 잦아져 읽기 리듬이 깨진다.

### 혼동 구분

콘텐츠 컨테이너 전체 폭과 항상 같지 않다. 영문 문자 수 기준을 한글에 동일하게 적용하면 밀도가 달라진다.

### 실행 명령

```text
본문 열의 최대 폭을 제한하고 실제 한글 문장으로 행 길이를 비교하라. 데스크톱에서도 문단이 화면 전체를 가로지르지 않게 하라.
```

### 설정·계약

영문 60~75자 같은 범위는 시험 기준일 뿐 한글 규칙이 아니다. 글꼴·크기·독자·매체를 함께 평가하고 표는 별도 폭을 쓴다.

### 검수

긴 글을 읽을 때 줄 시작을 잃지 않는지, 휴대폰에서는 과도하게 짧은 줄이 생기지 않는지 확인.

### 수정 명령

```text
폰트만 줄여 한 줄에 우겨 넣지 말고 본문 폭과 문장 단위를 조정하라.
```

<a name="d3-07"></a>
## D3-07 · 기준선 그리드

**Baseline Grid** · PDF 26쪽

### 뜻·쓰임

여러 텍스트 열과 페이지의 글자 기준선을 일정한 수직 간격에 맞추는 조판 체계다. 잡지·보고서의 여러 단을 가지런히 정렬할 때 쓰인다.

### 혼동 구분

박스의 상단 정렬이나 모든 요소 높이 통일과 다르다. 큰 제목·이미지 캡션에는 예외 규칙이 필요할 수 있다.

### 실행 명령

```text
두 단 본문을 14pt 기준선 간격에 맞추고 제목 뒤 공간을 그 배수로 조정하라. 표 내부는 가독성을 해치면 예외로 표시하라.
```

### 설정·계약

실제 폰트 메트릭과 본문 행간을 먼저 정한다. 웹에서 엄격한 기준선 맞춤은 확대·다국어와 충돌할 수 있어 필요 범위를 제한한다.

### 검수

좌우 단의 본문 기준선과 페이지를 넘긴 뒤의 수직 리듬이 안정적인지 확인.

### 수정 명령

```text
기준선을 맞추려고 텍스트를 잘라내지 말고 상하 공간과 예외 범위를 조정하라.
```

<a name="d3-08"></a>
## D3-08 · 고아줄·과부줄

**Widows / Orphans** · PDF 26쪽

### 뜻·쓰임

문단의 짧은 일부가 페이지·단의 처음이나 끝에 외롭게 남는 조판 문제다. CSS의 widows는 새 영역 위쪽, orphans는 이전 영역 아래쪽의 최소 줄 수를 제어한다.

### 혼동 구분

한글 번역은 관행 차이가 있으므로 위치를 말로 함께 지정한다. 제목만 페이지 끝에 남는 문제는 keep-with-next로 별도 다룬다.

### 실행 명령

```text
문단의 첫 줄만 페이지 아래에 남거나 마지막 줄만 다음 페이지 위로 넘어가지 않게 하라. 제목은 뒤의 본문 두 줄 이상과 함께 유지하라.
```

### 설정·계약

widows:2; orphans:2는 시작 예시다. 표·카드의 break-inside 회피와 함께 적용하되 긴 블록이 페이지보다 커지지 않게 한다.

### 검수

페이지 경계마다 홀로 남은 줄과 제목, 과도한 빈 공간을 확인.

### 수정 명령

```text
문서 전체 글자를 줄이지 말고 해당 문단·제목의 분할 규칙부터 수정하라.
```

<a name="d3-09"></a>
## D3-09 · 가변 폰트

**Variable Font** · PDF 27쪽

### 뜻·쓰임

하나의 파일에 굵기·폭·광학 크기 등 여러 축의 변화를 담는 폰트 형식이다. 반응형 타이포와 다양한 굵기 조절에 유용하다.

### 혼동 구분

모든 가변 폰트가 모든 축을 제공하지 않는다. 파일 용량과 렌더링 지원은 고정 폰트 여러 개와 비교해야 한다.

### 실행 명령

```text
선택 폰트의 실제 wght·wdth·opsz 축 범위를 확인하고 본문과 제목의 값을 명시하라. 지원되지 않는 축은 사용하지 마라.
```

### 설정·계약

font-weight 같은 고수준 속성을 우선하고 필요한 경우만 축 값을 직접 제어한다. 축 변경 시 글자 폭과 줄바꿈이 바뀔 수 있다.

### 검수

브라우저·PDF 출력에서 같은 굵기로 보이고 선택 축의 극단값에도 글리프가 정상인지 확인.

### 수정 명령

```text
지원 범위를 모른 채 wght 900을 요구하지 말고 파일의 축 메타데이터에 맞춰라.
```

<a name="d3-10"></a>
## D3-10 · 글리프·폴백·임베딩

**Glyph / Fallback / Font Embedding** · PDF 27쪽

### 뜻·쓰임

글리프는 문자에 대응하는 시각 형태, 폴백은 누락 문자를 대체 폰트로 표시하는 방식, 임베딩은 문서에 폰트 데이터를 포함하는 처리다. 다국어 PDF 납품에서 중요하다.

### 혼동 구분

텍스트를 윤곽선으로 바꾸는 것은 임베딩과 다르며 검색·복사·접근성 정보가 약해질 수 있다.

### 실행 명령

```text
PDF에 사용 글꼴을 허용 범위 내 임베딩하고 한글·수학 기호·통화·대시를 검사하라. 본문은 검색 가능한 텍스트로 유지하라.
```

### 설정·계약

부분집합 임베딩은 사용 글리프만 포함할 수 있다. 사용 허가와 라이선스 조건을 확인하고 폴백의 굵기·기준선 차이를 점검한다.

### 검수

다른 뷰어에서 네모 글자·대체 글꼴·복사 오류가 없는지, 필요한 문자열을 검색할 수 있는지 확인.

### 수정 명령

```text
특수문자를 삭제해 해결하지 말고 지원 글리프를 가진 폰트와 명시적인 대체 순서를 적용하라.
```
