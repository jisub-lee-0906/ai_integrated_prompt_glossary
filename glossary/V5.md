<a name="v5-01"></a>
## V5-01 · 색보정·색연출 (Color Correction / Color Grading)

**Color Correction / Color Grading** · PDF 83쪽

### 뜻·쓰임

Color correction은 노출·화이트밸런스·샷 일치 같은 기초 보정이고, grading은 작품의 분위기를 설계하는 색연출이다. 작업은 겹칠 수 있지만 색 문제를 고치기 전에 강한 룩을 입히면 일관성 확보가 어렵다.

### 혼동 구분

Correction은 기초 색·노출 정합, Grading은 표현 룩 설계다. LUT를 얹기 전에 입력 색공간을 확인한다.

### 실행 명령

```text
First neutralize white balance and match exposure across shots, then apply restrained teal shadows and warm highlights with natural skin tones.
```

### 설정·계약

소스 색공간·감마와 출력 기준을 먼저 정한다. SDR Rec.709 납품은 한 가지 예이며 HDR에 그대로 적용하지 않는다. LUT의 입력/출력 조건을 확인하고 스코프로 클리핑을 검사한다.

### 검수

피부·흰색 기준물·암부 디테일과 샷 간 색 일치, 색관리된 화면의 최종 결과를 확인.

### 수정 명령

```text
샷마다 피부가 달라지면 룩 강도 조정보다 중성 기준·노출 매칭을 먼저 하라.
```

<a name="v5-02"></a>
## V5-02 · 프레임 레이트 (Frame Rate (FPS))

**Frame Rate (FPS)** · PDF 83쪽

### 뜻·쓰임

1초에 표시하거나 기록하는 프레임 수다. 촬영 FPS, 타임라인 FPS, 납품 FPS가 다를 수 있으며, 프롬프트에 숫자를 적는 것만으로 파일 속성이 바뀌지는 않는다. 해상도·셔터·움직임과 함께 체감을 결정한다.

### 혼동 구분

촬영·타임라인·출력 FPS는 구분한다. 23.976과 24를 같은 값으로 처리하지 않는다.

### 실행 명령

```text
Create calm cinematic motion; set the delivery timeline to 24fps and report the actual exported frame rate in the file metadata.
```

### 설정·계약

24, 25, 30, 60fps와 23.976, 29.97fps를 구분한다. 10초×24fps는 240프레임이다. 24→30 변환은 중복·보간·속도 변경 중 어떤 방법인지 명시하고 오디오 동기를 확인한다.

### 검수

파일 메타데이터, 프레임 수, 재생 길이와 움직임의 일정함을 함께 검사.

### 수정 명령

```text
메타데이터에서 실제 FPS와 프레임 수를 확인하고 변환 방법을 명시하라.
```

<a name="v5-03"></a>
## V5-03 · 비트레이트 (Bitrate)

**Bitrate** · PDF 84쪽

### 뜻·쓰임

초당 기록하는 데이터량으로 보통 Mbps를 쓴다. 같은 코덱·조건에서는 화질과 용량에 영향을 주지만 숫자가 높다고 항상 좋은 것은 아니다. CBR은 일정 데이터율, VBR은 장면에 따라 데이터 배분을 조절한다.

### 혼동 구분

비트레이트는 데이터량이고 코덱은 압축 방식이다. 같은 Mbps라도 장면·인코더에 따라 화질이 다르다.

### 실행 명령

```text
Export a 1080p review copy using H.264 at a target video bitrate of 10 Mbps; inspect fast motion and gradients before approval.
```

### 설정·계약

10Mbps는 예시 시작값이며 납품처·장면에 맞춘다. 대략 용량(MB)=총 비트레이트(Mbps)×초÷8이므로 10Mbps 영상 60초는 약 75MB다. 오디오와 컨테이너 오버헤드는 추가된다.

### 검수

빠른 모션·잔디·연기·그라데이션의 블록과 밴딩, 실제 파일 크기를 확인.

### 수정 명령

```text
블록이 보이면 복잡한 구간을 기준으로 인코딩 설정과 목표 비트레이트를 재평가하라.
```

## V5-04 · 코덱 (Codec (H.264 / ProRes))

**Codec (H.264 / ProRes)** · PDF 84쪽

### 뜻·쓰임

영상을 부호화·복호화하는 방식이다. H.264는 전달·재생용 압축에 널리 쓰이고 ProRes는 편집·후반 작업에 쓰이는 계열이다. MP4와 MOV는 컨테이너이므로 확장자만 보고 코덱을 판정할 수 없다.

### 혼동 구분

코덱·컨테이너·픽셀 형식·알파는 서로 다른 속성이다. MOV나 MP4 확장자만으로 판단하지 않는다.

### 실행 명령

```text
Deliver an H.264 MP4 for review and a ProRes 4444 MOV master when alpha is required; state codec, resolution and frame rate.
```

### 설정·계약

일반적인 H.264 MP4 납품에는 알파를 기대하지 않는다. ProRes 422 계열은 알파가 없고 4444/4444 XQ는 알파를 지원한다. 비트 심도·색 샘플링·인코더 지원도 납품 환경에서 확인한다.

### 검수

실제 스트림 코덱과 알파 유무를 검사하고 수신자의 편집기에서 파일을 열어 본다.

### 수정 명령

```text
수신 편집기에서 스트림 정보와 알파를 실제로 열어 확인하라.
```

<a name="v5-05"></a>
## V5-05 · 비트 심도 (Bit Depth)

**Bit Depth** · PDF 85쪽

### 뜻·쓰임

채널 값을 표현하는 정밀도다. 8비트는 채널당 256단계, 10비트는 1024단계를 표현해 보정·그라데이션 여유에 영향을 준다.

### 혼동 구분

해상도나 색역 크기와 다르다. 8비트를 10비트로 저장해도 이미 잃은 계조가 복구되지는 않는다.

### 실행 명령

```text
강한 색보정이 필요한 소스는 가능한 원본 심도를 유지하고 중간 출력의 8비트 변환 여부를 보고하라.
```

### 설정·계약

입력·작업·출력 심도와 코덱 지원을 확인한다. 계산 정밀도와 저장 심도를 구분한다.

### 검수

하늘·연기·어두운 그라데이션에서 밴딩과 색 끊김이 없는지 확인.

### 수정 명령

```text
밴딩을 샤프닝으로 고치지 말고 원본 심도·중간 변환·압축을 점검하라.
```

## V5-06 · 크로마 서브샘플링 (Chroma Subsampling)

**Chroma Subsampling** · PDF 85쪽

### 뜻·쓰임

색차 정보를 휘도보다 낮은 공간 해상도로 저장하는 방식이다. 4:4:4·4:2:2·4:2:0 표기로 흔히 구별한다.

### 혼동 구분

해상도·비트 심도와 별개다. 일반적인 4:2:0은 가로·세로 색차 해상도가 줄어 작은 색 글자와 키잉 경계에 영향을 준다.

### 실행 명령

```text
크로마 키 중간 마스터는 색차 보존을 고려해 형식을 선택하고 검토본 4:2:0 변환은 최종 단계로 분리하라.
```

### 설정·계약

실제 소스·코덱·픽셀 형식을 확인한다. 숫자 표기는 색차 배치 관례도 있어 모든 경우를 단순 비율로만 해석하지 않는다.

### 검수

빨간 작은 글자·녹색 경계·가는 색 선의 번짐을 실제 출력에서 검사.

### 수정 명령

```text
해상도만 높이지 말고 중간 단계의 색차 손실을 줄여라.
```

## V5-07 · LUT (Look-up Table)

**Look-up Table** · PDF 86쪽

### 뜻·쓰임

입력 색 값을 다른 색 값으로 대응시키는 변환표다. 기술 색 변환 또는 창작 룩 적용에 쓰지만 두 용도를 구분해야 한다.

### 혼동 구분

어떤 영상에도 적용하는 만능 필터가 아니다. 입력 감마·색공간이 맞지 않으면 대비와 채도가 크게 틀어진다.

### 실행 명령

```text
LUT의 예상 입력과 출력 색공간을 확인하고 소스 변환 후 적용하라. 기술 변환과 창작 룩을 별도 단계로 기록하라.
```

### 설정·계약

1D/3D LUT·강도·적용 순서·클리핑을 확인한다. 자동 색관리와 동일 변환을 중복하지 않는다.

### 검수

피부·중성 회색·하이라이트가 정상이며 전후 노출 차이가 의도적인지 확인.

### 수정 명령

```text
LUT를 약하게만 섞지 말고 먼저 올바른 입력 변환을 맞춰라.
```

<a name="v5-08"></a>
## V5-08 · 웨이브폼·벡터스코프 (Waveform / Vectorscope)

**Waveform / Vectorscope** · PDF 86쪽

### 뜻·쓰임

영상 신호의 밝기 분포와 색차 방향·크기를 시각화하는 측정 도구다. 노출·클리핑·샷 매칭을 눈의 적응과 분리해 판단한다.

### 혼동 구분

화면의 미적 완성도를 자동 판정하는 도구는 아니다. 스코프 눈금은 신호·표준·표시 방식에 따라 해석해야 한다.

### 실행 명령

```text
색보정 전후 waveform과 vectorscope를 확인하고 흰 라벨·피부·암부의 클리핑과 샷 간 차이를 기록하라.
```

### 설정·계약

SDR/HDR·full/video range·스코프 모드를 먼저 맞춘다. 피부선은 참고 방향이지 모든 피부를 맞출 유일한 목표가 아니다.

### 검수

극단값에 정보가 몰려 사라지지 않고 기준 샷과 중요 영역이 일치하는지 확인.

### 수정 명령

```text
눈으로 밝기를 번갈아 추정하지 말고 같은 영역의 스코프 값을 비교하라.
```

<a name="v5-09"></a>
## V5-09 · 프록시 (Proxy)

**Proxy** · PDF 87쪽

### 뜻·쓰임

편집 부하를 줄이기 위해 원본과 연결한 가벼운 대체 미디어다. 고해상도·복잡한 코덱 소스를 원활히 편집할 때 쓴다.

### 혼동 구분

낮은 화질 최종 납품본과 다르다. 최종 출력에 원본이 다시 연결되는지 확인해야 한다.

### 실행 명령

```text
원본과 프레임·오디오 채널·타임코드가 대응하는 프록시를 만들고 최종 출력은 고해상도 원본으로 수행하라.
```

### 설정·계약

이름·연결 규칙·해상도·코덱·저장 위치를 정한다. 색관리와 화면비가 원본과 일치해야 한다.

### 검수

전환 시 구도·색·동기가 달라지지 않고 오프라인 원본을 빠짐없이 재연결하는지 확인.

### 수정 명령

```text
편집이 느리다고 모든 원본을 덮어 변환하지 말고 연결 가능한 프록시를 별도로 생성하라.
```

## V5-10 · GOP·인트라·인터 프레임 (GOP / Intra-frame / Inter-frame)

**GOP / Intra-frame / Inter-frame** · PDF 87쪽

### 뜻·쓰임

GOP는 압축 프레임의 묶음이며 intra는 프레임 내부, inter는 다른 프레임과의 관계를 활용한다. 탐색·편집·압축 효율에 영향을 준다.

### 혼동 구분

애니메이션 키프레임과 다르다. I-frame·IDR 등 용어의 정확한 역할은 코덱에 따라 구분된다.

### 실행 명령

```text
배포용 인코딩의 키프레임 간격을 납품처 요구에 맞추고 편집용 중간 코덱은 탐색 성능과 저장량을 비교하라.
```

### 설정·계약

GOP 길이·장면 전환·스트리밍 요구·인코더를 기록한다. 짧을수록 항상 화질이 좋은 것은 아니다.

### 검수

임의 탐색·컷 시작·스트리밍 구간에서 깨짐과 긴 응답 지연이 없는지 확인.

### 수정 명령

```text
확장자 변경으로 해결하지 말고 목적에 맞는 부호화 구조로 다시 인코딩하라.
```
