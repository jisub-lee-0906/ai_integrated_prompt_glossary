> 화면의 정렬·크기·상태를 어떤 규칙으로 반복할 것인가?

<a name="d2-01"></a>
## D2-01 · 시각적 위계 (Visual Hierarchy)

**Visual Hierarchy** · PDF 17쪽

### 뜻·쓰임

크기, 대비, 위치, 간격, 굵기를 조절해 정보를 읽는 순서를 만드는 원리다. 모든 요소를 강조하면 위계가 사라진다. ‘고급스럽게’ 대신 사용자에게 먼저 보여 줄 정보와 행동을 지정하면 효과적이다.

### 혼동 구분

위계는 무엇을 먼저 읽는지 결정한다. 단순히 모든 글자 크기를 키우는 것은 위계 강화가 아니다.

### 실행 명령

```text
Design a pricing page with a dominant headline, a clear recommended plan, one primary call to action and subdued secondary details.
```

### 설정·계약

예: 제목 32px, 본문 16px, 보조 14px를 출발점으로 삼되 실제 화면에서 조정한다. 우선순위 1~3과 기본 CTA를 정의하고, 색상만으로 상태나 중요도를 전달하지 않는다.

### 검수

5초 안에 화면의 목적과 다음 행동을 찾을 수 있는지, 제목 단계가 논리적인지 확인.

### 수정 명령

```text
버튼 세 개가 모두 강조되면 기본 행동 하나를 정하고 나머지 대비와 크기를 낮춰라.
```

<a name="d2-02"></a>
## D2-02 · 그리드 시스템 (Grid System)

**Grid System** · PDF 17쪽

### 뜻·쓰임

콘텐츠를 정렬하는 열·행·간격의 규칙이다. 구성 요소가 달라도 공통 기준선이 있으면 일관성이 유지된다. 그리드 열 수와 실제 카드 개수는 다르며 카드는 여러 열을 차지할 수 있다.

### 혼동 구분

그리드는 정렬 체계이고 카드 열 수는 그 체계 위의 배치다. 동일한 12열에서도 3개·4개 카드 구성이 가능하다.

### 실행 명령

```text
Create a desktop editorial layout on a 12-column grid, 24px gutters and generous margins; collapse to four columns on mobile.
```

### 설정·계약

1440px 화면에서 최대 콘텐츠 폭 1200px, gutter 24px 등을 설계 예시로 사용한다. 좁은 화면은 열 수·여백을 줄이고, 최소 콘텐츠 폭을 기준으로 중단점을 조정한다.

### 검수

헤더·본문·카드의 정렬선, 긴 제목의 줄바꿈, 중간 너비에서의 콘텐츠 넘침을 점검.

### 수정 명령

```text
폭이 바뀔 때 카드가 찌그러지면 최소 폭과 줄바꿈 조건을 추가하라.
```

<a name="d2-03"></a>
## D2-03 · 네거티브 스페이스 (Negative Space)

**Negative Space** · PDF 18쪽

### 뜻·쓰임

피사체 주변의 비어 있는 영역으로, 시선의 흐름과 텍스트 배치를 설계한다. 네거티브 프롬프트처럼 ‘제외할 내용’을 뜻하지 않는다. 빈 공간도 색·밝기·형태를 가진 적극적인 구도 요소다.

### 혼동 구분

네거티브 스페이스는 구도의 빈 영역이고 padding·margin은 이를 구현하는 박스 간격이다.

### 실행 명령

```text
Editorial hero image with the subject in the right third, uncluttered left half reserved for headline text, soft off-white background.
```

### 설정·계약

‘왼쪽 약 45%는 제목 영역’처럼 위치와 용도를 함께 지정한다. 정확한 여백은 최종 캔버스에서 맞추고, 모바일 크롭에서도 피사체와 제목 영역이 유지되도록 별도 구도를 준비한다.

### 검수

실제 제목을 얹어 배경 간섭과 글자 대비를 검사하고 세로형 크롭에서도 읽히는지 확인.

### 수정 명령

```text
여백을 무작정 확대하지 말고 제목·본문·CTA가 묶이는 간격과 그룹 사이 간격을 나눠라.
```

<a name="d2-04"></a>
## D2-04 · 오토 레이아웃 (Auto Layout)

**Auto Layout** · PDF 18쪽

### 뜻·쓰임

자식 요소의 크기와 간격에 따라 컨테이너가 자동으로 늘어나거나 정렬되는 규칙이다. 버튼·카드·목록의 문구 변경과 다국어 대응에 유용하다.

### 혼동 구분

고정 좌표 배치와 다르며 도구의 Hug/Fill/Fixed 개념은 CSS의 대응 관계와 완전히 같지 않을 수 있다.

### 실행 명령

```text
카드의 콘텐츠 영역은 세로 오토 레이아웃, 버튼 행은 가로 배치로 만들고 제목이 3줄이어도 버튼과 충돌하지 않게 하라.
```

### 설정·계약

방향·gap·padding·정렬·줄바꿈·최소/최대 크기를 정한다. 텍스트는 내용에 맞춰 늘리고 필수 버튼이 밀려 사라지지 않게 한다.

### 검수

짧은 제목·긴 제목·큰 글꼴·버튼 추가 시 겹침 없이 배치되는지 확인.

### 수정 명령

```text
수동 y좌표를 계속 늘리지 말고 콘텐츠 높이를 따라 흐르는 컨테이너로 바꿔라.
```

<a name="d2-05"></a>
## D2-05 · 간격 척도 (Spacing Scale)

**Spacing Scale** · PDF 19쪽

### 뜻·쓰임

화면에서 사용하는 간격을 제한된 수열로 정의하는 규칙이다. 그룹의 관련성·호흡·밀도를 일관되게 표현하고 임의 값의 증가를 줄인다.

### 혼동 구분

모든 간격을 같게 만드는 것이 아니다. 같은 그룹 안은 좁게, 그룹 사이는 넓게 하는 관계가 중요하다.

### 실행 명령

```text
4·8·12·16·24·32px 간격 토큰을 만들고 라벨-입력, 필드 간, 섹션 간 간격을 각각 연결하라.
```

### 설정·계약

수열은 예시다. 반응형 축소 규칙과 광학적 예외를 문서화하고 음수 마진으로 구조 문제를 덮지 않는다.

### 검수

유사한 컴포넌트가 같은 간격 규칙을 따르는지, 좁은 화면에서도 그룹이 구별되는지 확인.

### 수정 명령

```text
값을 1px씩 손대기 전에 관련성이 같은 간격을 동일 토큰으로 묶어라.
```

<a name="d2-06"></a>
## D2-06 · 컴포넌트 변형 (Component Variants)

**Component Variants** · PDF 19쪽

### 뜻·쓰임

하나의 컴포넌트가 크기·강조도·상태·아이콘 유무에 따라 갖는 규칙적인 변형이다. 버튼이나 입력창의 일관된 재사용에 쓰인다.

### 혼동 구분

인스턴스를 분리 복제한 것과 다르다. 모든 조합이 유효한지 결정하지 않으면 변형 수만 폭증한다.

### 실행 명령

```text
버튼에 size=sm/md, intent=primary/secondary, state=idle/loading/disabled를 정의하고 불가능한 조합과 접근성 이름 규칙을 문서화하라.
```

### 설정·계약

속성별 책임을 분리하고 기본값을 정한다. loading에서도 너비를 유지하며 disabled와 loading의 의미를 구별한다.

### 검수

변형 행렬을 렌더링해 대비·정렬·아이콘 간격·상태 전이가 일관적인지 확인.

### 수정 명령

```text
색만 다른 복제본을 늘리지 말고 공통 구조와 명시적인 variant 속성으로 통합하라.
```

<a name="d2-07"></a>
## D2-07 · 디자인 토큰 (Design Tokens)

**Design Tokens** · PDF 20쪽

### 뜻·쓰임

반복되는 시각적 결정을 이름 붙인 값으로 관리하는 방식이다. color.brand.500 같은 원시 값과 color.action.primary 같은 의미 기반 이름을 분리하면 테마나 브랜드 변경을 일관되게 적용하기 쉽다.

### 혼동 구분

토큰은 공유되는 값과 의미의 계약이다. 컴포넌트는 그 값을 사용하는 UI 단위이므로 서로 대체하지 않는다.

### 실행 명령

```text
Define semantic design tokens for color, spacing, typography and radius; provide light and dark themes plus component usage examples.
```

### 설정·계약

spacing은 4/8/12/16/24/32px 같은 척도로 시작할 수 있다. 값의 단위, 별칭 해석, 출력 JSON/CSS 형식을 명시한다. 특정 토큰 명명법을 업계 유일 표준처럼 전제하지 않는다.

### 검수

토큰 하나를 바꿨을 때 관련 컴포넌트가 함께 바뀌는지, 하드코딩 값이 남는지 검사.

### 수정 명령

```text
원시 색상을 바꿨는데 일부만 바뀌면 별칭 연결과 하드코딩 사용처를 점검하라.
```

<a name="d2-08"></a>
## D2-08 · 미세 상호작용 (Microinteraction)

**Microinteraction** · PDF 20쪽

### 뜻·쓰임

버튼 누르기, 저장, 입력 검증처럼 작은 행동에 대한 피드백 설계다. 트리거, 처리 규칙, 피드백, 반복 조건을 함께 정의해야 장식적 애니메이션에 머무르지 않는다. 비동기 처리에는 실패 경로도 필요하다.

### 혼동 구분

미세 상호작용은 행동에 대한 피드백이다. 주목만 끄는 반복 장식과 달리 시작·종료·실패 조건이 있다.

### 실행 명령

```text
Specify a save-button microinteraction: idle, saving, success and failure; use subtle motion and an accessible status announcement.
```

### 설정·계약

예: 160ms 색 전환과 240ms 성공 표시를 초기값으로 검토한다. 실제 네트워크 대기 시간을 애니메이션 길이로 가정하지 않는다. reduced-motion에서는 이동을 줄이고 상태 텍스트를 유지한다.

### 검수

빠른 연속 클릭, 키보드 조작, 실패 후 재시도에도 상태가 명확하고 중복 저장이 없는지 확인.

### 수정 명령

```text
성공 애니메이션이 API 완료 전에 나오면 실제 처리 상태와 표시 시점을 연결하라.
```

<a name="d2-09"></a>
## D2-09 · 대비와 접근성 (Contrast &amp; Accessibility)

**Contrast &amp; Accessibility** · PDF 21쪽

### 뜻·쓰임

전경과 배경의 명도 차이는 읽기 쉬움의 핵심 요소다. 접근성은 대비뿐 아니라 키보드, 의미 구조, 대체 텍스트, 오류 안내까지 포함한다. 화면 이미지가 보기 좋다는 것만으로 접근성 적합성을 판정할 수 없다.

### 혼동 구분

색 대비 충족은 접근성의 일부다. 입력 라벨·키보드 조작·의미 구조와 함께 검토한다.

### 실행 명령

```text
Design accessible form controls with readable text, visible keyboard focus, persistent labels and error messages that do not rely on color alone.
```

### 설정·계약

WCAG 2.2 AA 텍스트 기준은 일반 4.5:1, 큰 텍스트 3:1이다. 큰 텍스트는 18pt 이상 또는 굵은 14pt 이상이다. 플레이스홀더를 라벨로 대체하지 말고 실제 조합을 측정한다.

### 검수

일반·hover·focus·error 상태의 대비를 측정하고 키보드로 전체 과업을 수행.

### 수정 명령

```text
색을 진하게 바꾼 뒤에도 오류를 못 찾으면 오류 요약·필드 연결·초점 이동을 추가하라.
```

<a name="d2-10"></a>
## D2-10 · 시맨틱 HTML (Semantic HTML)

**Semantic HTML** · PDF 21쪽

### 뜻·쓰임

문서 요소의 의미에 맞는 HTML을 사용하는 방식이다. 제목·탐색·버튼·폼 구조가 브라우저와 보조기기에 전달되어 기본 동작을 재사용할 수 있다.

### 혼동 구분

div에 클릭 이벤트를 붙이는 것과 native button은 키보드·비활성·폼 동작에서 다르다. ARIA는 의미를 보완하지만 잘못된 구조를 자동 수정하지 않는다.

### 실행 명령

```text
페이지를 header/nav/main/footer로 나누고 행동은 button, 이동은 a로 구현하라. 제목 계층과 모든 입력의 label 연결을 제공하라.
```

### 설정·계약

문서에서 main은 주된 콘텐츠를 가리킨다. 시각적 크기 때문에 heading 수준을 고르지 말고 구조 순서를 유지한다.

### 검수

키보드만으로 조작하고 접근성 트리에서 이름·역할·상태가 올바르게 보이는지 확인.

### 수정 명령

```text
클릭 가능한 div를 기본 요소로 바꾸되 기존 시각 스타일과 포커스 표시를 함께 유지하라.
```
