> 실무 용어를 어떤 생성 제어와 결합해야 결과를 유지하며 수정할 수 있는가?

생성 제어는 실무 용어의 역할을 보완한다. 모델마다 같은 숫자의 뜻이 다르므로 하나의 프리셋을 모든 도구에 적용하지 않는다. 참조·설정·선택 결과를 기록하고 필요한 범위만 수정한다.

<a name="x2-01"></a>
## X2-01 · 네거티브 프롬프트

**Negative Prompt** · PDF 149쪽

### 뜻·쓰임

원하지 않는 요소나 특성을 별도 조건으로 제시하는 방식이다. 도구마다 전용 필드, 명령 문법, 지원 여부가 다르다. 부정어를 본문에 나열하는 것과 모델의 네거티브 조건 입력은 동일하지 않다.

### 혼동 구분

네거티브 입력은 모델마다 지원·효과가 다르다. 부정어를 긴 본문에 넣는 것과 별도 조건 필드는 다르다.

### 실행 명령

```text
Positive: clean product illustration, coherent silhouette. Negative field, if supported: extra objects, illegible lettering, compression artifacts.
```

### 설정·계약

Midjourney의 --no와 Diffusers의 negative_prompt는 서로 다른 입력이다. 본문에는 원하는 장면을 먼저 구체화하고 제외 목록은 짧게 유지한다. Runway Gen-4 지침은 긍정 표현을 권장하므로 기계적으로 이식하지 않는다.

### 검수

동일 조건에서 제외 목록 유무를 비교하고 원하는 디테일까지 함께 사라지지 않는지 확인.

### 수정 명령

```text
원하는 결과를 먼저 긍정 문장으로 쓰고 지원되는 제외 입력에 필요한 항목만 넣어라.
```

<a name="x2-02"></a>
## X2-02 · 시드

**Seed** · PDF 149쪽

### 뜻·쓰임

생성의 난수 초기 조건을 지정하는 값이다. 같은 환경에서 변수를 비교할 때 유용하지만 단독으로 동일 결과를 보장하지는 않는다.

### 혼동 구분

모델·스케줄러·라이브러리·하드웨어·참조 입력이 달라지면 같은 seed도 결과가 달라질 수 있다.

### 실행 명령

```text
구도 비교에는 seed를 고정하고 조명 조건 하나만 바꿔 4개 시안을 생성하라. 모델·버전·설정·참조 파일을 함께 기록하라.
```

### 설정·계약

지원 범위·랜덤 생성 여부·배치별 seed 정책을 확인한다. 특정 공급자의 숫자 범위를 다른 도구에 그대로 적용하지 않는다.

### 검수

조건을 다시 실행했을 때 어느 수준까지 재현되는지 실제로 비교.

### 수정 명령

```text
seed만 전달하지 말고 생성 환경과 입력 자산을 하나의 기록으로 묶어라.
```

<a name="x2-03"></a>
## X2-03 · 가이던스

**Guidance / CFG** · PDF 150쪽

### 뜻·쓰임

텍스트 등 조건을 생성에 얼마나 강하게 반영할지 조절하는 계열의 제어다. 이름·정의·효과는 모델과 파이프라인에 따라 다르다.

### 혼동 구분

값이 높다고 항상 지시 준수·품질이 좋아지는 것은 아니다. 과한 대비·색 포화·형태 손상이 생길 수 있다.

### 실행 명령

```text
선택 모델의 권장 범위 안에서 guidance를 단계적으로 비교하고 형태·색·지시 준수의 균형을 평가하라.
```

### 설정·계약

모델·증류 여부·guidance 구현·네거티브 지원을 확인한다. SDXL의 예시 값을 다른 계열에 일괄 적용하지 않는다.

### 검수

같은 조건에서 원하는 속성이 강화되면서 아티팩트가 증가하지 않는지 확인.

### 수정 명령

```text
값부터 최대로 올리지 말고 모호한 대상·관계 표현을 먼저 구체화하라.
```

<a name="x2-04"></a>
## X2-04 · 샘플러·스텝

**Sampler / Scheduler / Steps** · PDF 150쪽

### 뜻·쓰임

확산 생성의 상태를 갱신하는 방법과 반복 횟수에 관련된 제어다. 품질·시간·재현성을 비교할 때 함께 기록한다.

### 혼동 구분

step 수만 늘린다고 디테일이 계속 좋아지지 않는다. 가속·증류 모델은 특정 알고리즘과 적은 스텝에 맞춰져 있을 수 있다.

### 실행 명령

```text
현재 체크포인트가 지원하는 scheduler와 step 조합을 사용하고 동일 해상도에서 시간·아티팩트·구도 유지성을 비교하라.
```

### 설정·계약

도구 UI의 sampler 이름과 라이브러리 scheduler가 정확히 대응하는지 확인한다. 전체 설정을 기록한다.

### 검수

같은 목표 품질에서 필요한 시간과 실패율을 비교하고 지나친 스텝 비용을 피한다.

### 수정 명령

```text
다른 모델의 유명 프리셋을 복사하지 말고 선택 모델의 실행 계약부터 확인하라.
```

<a name="x2-05"></a>
## X2-05 · 변형 강도

**Denoising Strength / Strength** · PDF 151쪽

### 뜻·쓰임

이미지 기반 생성에서 원본을 얼마나 변경할지에 영향을 주는 제어다. 리스타일링·구도 유지·부분 수정에서 조절한다.

### 혼동 구분

가이던스와 다른 축이다. strength의 의미·범위·실제 스텝 연동은 파이프라인에 따라 다르다.

### 실행 명령

```text
원본 실루엣을 유지하는 낮은 변형 강도부터 시험하고 재질 변화가 부족할 때만 점진적으로 높여라.
```

### 설정·계약

모델·입력 해상도·step 수·마스크·참조 강도를 함께 기록한다. 얼굴·로고처럼 보존할 부위를 지정한다.

### 검수

원하는 표면 변화와 원래 구조 보존이 동시에 충족되는지 확인.

### 수정 명령

```text
원본이 너무 달라지면 프롬프트를 길게 늘리기보다 변형 범위와 강도를 줄여라.
```

<a name="x2-06"></a>
## X2-06 · 인페인팅

**Inpainting** · PDF 151쪽

### 뜻·쓰임

이미지의 선택 영역을 마스크로 지정해 채우거나 바꾸는 방식이다. 물체 제거·손 수정·배경 교체 등 국소 변경에 쓰인다.

### 혼동 구분

모든 도구가 마스크 밖 픽셀을 완전히 보존하는 것은 아니다. 마스크의 흰색/검정 의미도 인터페이스별 확인이 필요하다.

### 실행 명령

```text
제품과 로고는 유지하고 오른쪽 배경의 불필요한 물체만 마스크로 제거하라. 경계의 그림자·반사 연결을 자연스럽게 복원하라.
```

### 설정·계약

마스크 영역·feather·문맥 패딩·강도·보존 범위를 정한다. Diffusers의 일반 인페인트는 흰 영역을 수정 대상으로 사용한다.

### 검수

수정 영역 경계와 비선택 영역의 변화, 반복 무늬·그림자 연결을 확인.

### 수정 명령

```text
작은 오류 때문에 전체 이미지를 재생성하지 말고 필요한 영역만 수정하라.
```

<a name="x2-07"></a>
## X2-07 · 아웃페인팅

**Outpainting** · PDF 152쪽

### 뜻·쓰임

기존 이미지 바깥으로 캔버스를 확장해 새로운 영역을 생성하는 작업이다. 화면비 변경·여백 확보·배경 확장에 유용하다.

### 혼동 구분

단순 확대·늘이기와 다르다. 원본 프레임 밖의 내용은 새로 만들어지는 것이므로 실제 장면의 증거로 간주하지 않는다.

### 실행 명령

```text
가로 광고를 세로 캔버스로 확장하되 제품 위치·크기는 유지하고 상단에는 제목용 여백, 하단에는 자연스러운 바닥을 생성하라.
```

### 설정·계약

확장 방향·픽셀 수·겹침 문맥·원본 고정·투영·광원 조건을 정한다.

### 검수

경계에서 선·색·원근·그림자가 이어지고 원본 제품이 변하지 않았는지 확인.

### 수정 명령

```text
원본을 세로로 늘리지 말고 필요한 방향의 배경만 확장하라.
```

<a name="x2-08"></a>
## X2-08 · 구조 조건 제어

**ControlNet / Structural Conditioning** · PDF 152쪽

### 뜻·쓰임

포즈·윤곽·깊이 같은 보조 입력으로 생성 구조를 유도하는 방식이다. 원하는 구도·자세를 유지하며 스타일을 바꿀 때 쓰인다.

### 혼동 구분

ControlNet은 특정 기술 계열이고 모든 참조 기반 생성이 같은 구현은 아니다. 조건 맵의 오류도 결과로 전파될 수 있다.

### 실행 명령

```text
참조의 depth 또는 pose 조건을 사용해 제품 배치·인물 자세를 유지하고 색·재질만 변경하라. 조건 입력과 결과를 함께 제공하라.
```

### 설정·계약

호환 모델·전처리기·강도·적용 구간·해상도를 확인한다. 여러 조건이 충돌하면 우선순위를 정한다.

### 검수

포즈·가림·원근은 유지되면서 스타일 변화가 적용되는지 확인.

### 수정 명령

```text
조건 강도만 올리지 말고 잘못된 포즈 점·깊이 경계를 먼저 수정하라.
```

<a name="x2-09"></a>
## X2-09 · LoRA·어댑터

**LoRA / Model Adapter** · PDF 153쪽

### 뜻·쓰임

기본 모델에 추가 학습된 작은 가중치 등을 결합해 스타일·대상 표현을 조절하는 방식이다. 반복 프로젝트의 특정 표현을 유도할 때 쓴다.

### 혼동 구분

프롬프트 단어와 다르며 모델 계열·버전 호환성이 필요하다. 강도를 높이면 과적합된 특징과 형태 왜곡이 나타날 수 있다.

### 실행 명령

```text
호환되는 LoRA와 권장 트리거를 확인하고 낮은 가중치부터 비교하라. 기본 모델·어댑터 버전·강도·출처를 기록하라.
```

### 설정·계약

여러 어댑터 조합의 충돌과 사용 조건을 확인한다. 특정 인물·브랜드 자료 사용은 권리와 입력 범위를 점검한다.

### 검수

스타일 일관성과 원래 구도·대상의 정확성이 함께 유지되는지 확인.

### 수정 명령

```text
어댑터를 계속 추가하기보다 목적별로 최소 조합을 비교하라.
```

<a name="x2-10"></a>
## X2-10 · 참조 일관성

**Reference Consistency** · PDF 153쪽

### 뜻·쓰임

여러 결과에서 같은 대상·스타일·공간 특징을 유지하기 위한 입력·검수 전략이다. 시리즈 이미지·스토리보드·영상 샷 연결에 핵심이다.

### 혼동 구분

단일 보편 파라미터 이름이 아니라 제작 목표다. 같은 seed만으로 인물·제품의 장면 간 정체성이 보장되지는 않는다.

### 실행 명령

```text
제품 참조 시트에서 실루엣·색·버튼 수·로고 위치를 고정 특징으로 정의하고 모든 샷을 그 목록으로 검사하라.
```

### 설정·계약

참조 이미지·턴어라운드·모델·우선순위·허용 변화·결과 버전을 함께 관리한다.

### 검수

각 샷의 특징 수·위치·비율이 유지되고 가림 뒤 재등장에도 바뀌지 않는지 확인.

### 수정 명령

```text
‘같은 제품’만 반복하지 말고 바뀌면 안 되는 식별 특징을 구체적으로 적어라.
```
