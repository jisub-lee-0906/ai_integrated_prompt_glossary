> 소리 크기·대사·시간 정보를 어떤 단위와 파일로 요구할 것인가?

소리의 평균 크기와 최대 피크, 음색과 잡음은 서로 다른 문제다. 매체의 현재 납품 기준을 확인하고 프로그램 전체를 측정한다. 자막은 전사·의미·읽기 시간·시간 동기까지 검수한다.

**작업 순서:** 대사 명료도 → 레벨·음색 → 시간 동기 → 자막 → 전달 파일

<a name="v6-01"></a>
## V6-01 · 샘플레이트 (Sample Rate)

**Sample Rate** · PDF 89쪽

### 뜻·쓰임

오디오 신호를 1초에 몇 번 샘플링하는지 나타내며 Hz로 표현한다. 영상과 오디오의 작업 설정을 맞추고 리샘플링을 관리할 때 쓴다.

### 혼동 구분

오디오 비트 심도·비트레이트와 다르다. 48kHz를 잘못된 속도로 해석하면 길이와 피치가 바뀔 수 있다.

### 실행 명령

```text
영상 프로젝트의 오디오 작업을 48kHz로 통일하고 다른 소스는 정상 리샘플링하라. 속도 해석 변경으로 대체하지 마라.
```

### 설정·계약

48kHz는 일반 영상 작업의 예시다. 원본 유지본과 변환본을 구분하고 채널 수·동기·길이를 확인한다.

### 검수

긴 영상 끝까지 립싱크가 유지되고 변환 후 피치·길이가 바뀌지 않는지 확인.

### 수정 명령

```text
샘플레이트 라벨만 고치지 말고 실제 리샘플링 처리를 사용하라.
```

<a name="v6-02"></a>
## V6-02 · 라우드니스 (Loudness / LUFS)

**Loudness / LUFS** · PDF 89쪽

### 뜻·쓰임

청감 가중을 반영해 평균적인 소리 크기를 측정하는 지표다. 여러 영상·에피소드의 체감 음량을 맞출 때 쓴다.

### 혼동 구분

순간 피크와 다르다. integrated·short-term·momentary는 측정 시간 범위가 다르며 무조건 하나의 목표값을 모든 매체에 적용하지 않는다.

### 실행 명령

```text
최종 믹스의 integrated LUFS와 true peak를 측정해 납품처 목표에 맞추고 대사 명료도를 유지하라. 목표값의 출처를 기록하라.
```

### 설정·계약

플랫폼·방송 규격을 먼저 확인한다. 예시 수치를 업계 공통 기준으로 쓰지 말고 전체 프로그램 범위를 측정한다.

### 검수

작은 스피커에서도 대사가 들리고 장면 전환에 체감 음량이 갑자기 튀지 않는지 확인.

### 수정 명령

```text
파형 최고점만 정규화하지 말고 프로그램 전체 라우드니스와 피크를 함께 조정하라.
```

**함께 구분할 용어:** [트루 피크 / True Peak / dBTP](V6.md#v6-03)

<a name="v6-03"></a>
## V6-03 · 트루 피크 (True Peak / dBTP)

**True Peak / dBTP** · PDF 90쪽

### 뜻·쓰임

디지털 샘플 사이를 복원할 때 발생할 수 있는 최대 피크를 추정하는 값이다. 압축·재생 과정의 과부하 여유를 관리하는 데 쓴다.

### 혼동 구분

샘플 피크 dBFS와 같지 않다. 샘플이 0dBFS 아래여도 복원 파형의 피크가 더 높을 수 있다.

### 실행 명령

```text
인코딩 후 파일의 true peak를 다시 측정하고 납품처 상한 아래로 제한하라. 리미터 적용 전후 왜곡을 청취하라.
```

### 설정·계약

측정기·리미터·오버샘플링·출력 코덱을 기록한다. -1dBTP 같은 값은 특정 납품 예시일 뿐 보편 규격이 아니다.

### 검수

강한 자음·타격음에서 거친 왜곡과 인코딩 후 상한 초과가 없는지 확인.

### 수정 명령

```text
전체 볼륨을 감으로 낮추지 말고 실제 최종 파일의 true peak를 측정하라.
```

**함께 구분할 용어:** [라우드니스 / Loudness / LUFS](V6.md#v6-02)

<a name="v6-04"></a>
## V6-04 · 이퀄라이저 (Equalization (EQ))

**Equalization (EQ)** · PDF 90쪽

### 뜻·쓰임

주파수 대역별로 크기를 조절해 음색·명료도·공간 충돌을 정리하는 처리다. 대사 저역 잡음이나 음악과 목소리의 겹침을 조절할 때 쓴다.

### 혼동 구분

노이즈 제거·압축과 다르다. 특정 대역을 무조건 깎는 고정 처방은 화자의 음색을 손상시킬 수 있다.

### 실행 명령

```text
대사의 불필요한 저역과 탁한 공명을 확인해 제한적으로 보정하고 음악의 대사 겹침 대역을 줄여라.
```

### 설정·계약

주파수·gain·Q·필터 종류를 기록한다. solo뿐 아니라 전체 믹스에서 비교하고 출력 레벨을 맞춰 A/B한다.

### 검수

말의 두께·치찰음·명료도가 자연스럽고 보정 후 얇고 날카로워지지 않는지 확인.

### 수정 명령

```text
보컬마다 같은 프리셋을 적용하지 말고 실제 문제 대역을 찾아 조절하라.
```

<a name="v6-05"></a>
## V6-05 · 다이내믹 압축 (Compression / Dynamic Range Control)

**Compression / Dynamic Range Control** · PDF 91쪽

### 뜻·쓰임

큰 소리를 기준에 따라 줄여 레벨 변동을 관리하는 처리다. 인터뷰 대사의 크기를 고르게 만들거나 음악의 에너지를 정리할 때 쓴다.

### 혼동 구분

파일 압축 코덱과 다른 의미다. loudness 정규화만으로 피크·구간별 변동이 자동으로 원하는 모양이 되지는 않는다.

### 실행 명령

```text
대사에 부드러운 압축을 적용하되 호흡과 강세를 남기고 threshold·ratio·attack·release와 gain reduction을 보고하라.
```

### 설정·계약

숫자는 소스에 맞춰 정한다. 너무 빠른 attack은 타격감을, 짧은 release는 자연스러움을 손상시킬 수 있다.

### 검수

펌핑·호흡 증폭·배경 소음 증가와 지나친 레벨 평탄화가 없는지 확인.

### 수정 명령

```text
압축량을 늘리기 전에 큰 편차 구간을 클립 게인으로 정리하라.
```

<a name="v6-06"></a>
## V6-06 · 덕킹·사이드체인 (Ducking / Sidechain)

**Ducking / Sidechain** · PDF 91쪽

### 뜻·쓰임

대사 같은 신호를 기준으로 음악 등 다른 신호의 레벨을 내려 공간을 만드는 방식이다. 내레이션이 나올 때 배경음을 자동 조절한다.

### 혼동 구분

모든 sidechain이 덕킹은 아니며 음악 전체를 계속 작게 두는 것과 다르다. 시작·복귀 타이밍이 청감에 중요하다.

### 실행 명령

```text
대사 시작 전에 음악이 자연스럽게 내려가고 문장 사이 짧은 쉼에서는 급격히 다시 커지지 않도록 덕킹하라.
```

### 설정·계약

감쇄량·attack·hold·release·검출 신호를 정한다. 긴 무음과 짧은 호흡을 구분한다.

### 검수

음악이 숨 쉬듯 출렁이지 않고 대사 자음이 첫 순간부터 들리는지 확인.

### 수정 명령

```text
자동 덕킹만 믿지 말고 문장 경계의 레벨 곡선을 수동 보정하라.
```

## V6-07 · 노이즈 제거·룸톤 (Noise Reduction / Room Tone)

**Noise Reduction / Room Tone** · PDF 92쪽

### 뜻·쓰임

노이즈 제거는 불필요한 잡음을 줄이는 처리이고 룸톤은 공간의 자연스러운 배경음이다. 대사 편집의 끊긴 구간을 자연스럽게 연결할 때 함께 다룬다.

### 혼동 구분

완전한 무음이 항상 좋은 결과는 아니다. 과한 제거는 금속성·물결 같은 인공음을 만들 수 있다.

### 실행 명령

```text
지속적인 팬 소음을 줄이되 대사의 질감을 보존하고 편집 공백에는 같은 장소의 룸톤을 낮게 이어라.
```

### 설정·계약

노이즈 프로파일·강도·대사 보호·전환 길이를 정한다. 원본과 같은 음량으로 비교한다.

### 검수

단어 끝·숨소리·잔향이 잘리지 않고 컷에서 배경 공간이 갑자기 바뀌지 않는지 확인.

### 수정 명령

```text
소리를 전부 게이트로 끊지 말고 제거 강도를 줄이고 자연스러운 배경을 유지하라.
```

<a name="v6-08"></a>
## V6-08 · 스템·채널 구성 (Stems / Channel Layout)

**Stems / Channel Layout** · PDF 92쪽

### 뜻·쓰임

대사·음악·효과 같은 그룹을 별도 파일로 내보낸 것이 stem이다. 채널 구성은 mono·stereo·다채널의 배치 계약이다.

### 혼동 구분

한 개 스테레오 믹스와 분리 stem은 다르다. 각 stem의 합이 마스터와 다를 수 있는 버스 처리도 확인해야 한다.

### 실행 명령

```text
대사·음악·효과 stem을 동일 시작점·길이·샘플레이트로 출력하고 stereo master와 합산 검증하라.
```

### 설정·계약

포함 효과·버스 처리·채널 순서·테일·파일 이름을 정한다. 모노 대사를 임의로 넓은 스테레오로 만들지 않는다.

### 검수

동일 위치에 합쳤을 때 동기와 믹스 의도가 재현되고 채널이 뒤집히지 않는지 확인.

### 수정 명령

```text
각 파일의 앞 무음을 따로 잘라내지 말고 공통 시간 기준을 유지하라.
```

<a name="v6-09"></a>
## V6-09 · 자막·캡션 (Subtitles / Captions)

**Subtitles / Captions** · PDF 93쪽

### 뜻·쓰임

자막은 발화·번역을 텍스트로 전달하고 captions는 화자·중요한 비언어 소리까지 포함하는 접근성 문맥에서 쓰인다.

### 혼동 구분

영상에 구운 글자와 선택 가능한 sidecar 파일은 다르다. 자동 전사는 맞춤법·고유명사·시간 동기를 검수해야 한다.

### 실행 명령

```text
한글 자막 SRT와 화면 검토본을 제공하라. 의미 단위로 줄을 나누고 고유명사·화자·필요한 소리 설명을 교정하라.
```

### 설정·계약

최대 줄 수·읽기 속도·최소 표시 시간·안전 영역은 매체와 독자에 맞춘다. SRT는 프레임 번호 대신 시간값을 쓴다.

### 검수

발화와 표시가 맞고 조사·이름 중간에서 어색하게 줄바꿈되지 않는지 확인.

### 수정 명령

```text
한 화면에 긴 문장을 우겨 넣지 말고 의미·호흡 기준으로 분할하라.
```

<a name="v6-10"></a>
## V6-10 · 타임코드 (Timecode)

**Timecode** · PDF 93쪽

### 뜻·쓰임

미디어의 위치를 시·분·초·프레임 등으로 식별하는 주소 체계다. 수정 의견·다중 소스 동기·재연결에서 기준점 역할을 한다.

### 혼동 구분

재생 경과 시간과 시작 타임코드는 다를 수 있다. Drop-frame은 실제 프레임 삭제가 아니라 시간 오차 보정용 번호 체계다.

### 실행 명령

```text
수정 목록에 소스 타임코드와 타임라인 타임코드를 구분하고 FPS·시작값·DF/NDF 여부를 표시하라.
```

### 설정·계약

29.97 등 비정수 프레임 레이트와 번호 체계를 맞춘다. 번인 검토본과 깨끗한 마스터를 분리한다.

### 검수

같은 타임코드가 리뷰어와 편집자에게 같은 프레임을 가리키는지 확인.

### 수정 명령

```text
‘1분쯤’ 대신 파일 버전·시간 기준·정확한 위치를 함께 전달하라.
```
