<a name="x1-01"></a>
## X1-01 · 크리에이티브 브리프

**Creative Brief** · PDF 143쪽

### 뜻·쓰임

목표·대상·메시지·사용처·제약을 요약한 제작 기준이다. 스타일 단어를 고르기 전에 무엇을 해결할지 합의하는 데 쓰인다.

### 혼동 구분

긴 프롬프트 자체와 다르다. 실행 도구가 바뀌어도 유지할 제품 목적과 제작 제약을 담는다.

### 실행 명령

```text
구독 서비스 광고 브리프에 대상 사용자, 핵심 메시지 하나, 사용 채널, 금지 표현, 필요한 산출물과 성공 기준을 명시하라.
```

### 설정·계약

필수·선호·탐색 가능 항목을 나누고 참조의 어느 특성을 차용하는지 적는다.

### 검수

결과의 디자인·영상·코드 선택이 동일 목표를 지원하고 요구 간 충돌이 없는지 확인.

### 수정 명령

```text
‘고급스럽게’ 대신 대상·메시지·톤의 구체적 기준을 먼저 보완하라.
```

<a name="x1-02"></a>
## X1-02 · 인수 기준

**Acceptance Criteria** · PDF 143쪽

### 뜻·쓰임

산출물을 완료로 인정할 구체적인 조건이다. 검수 의견을 취향 수준에서 재현 가능한 판단으로 옮긴다.

### 혼동 구분

활동 목록과 다르다. ‘테스트 작성’보다 ‘중복 요청에도 주문 하나’가 결과 기준이다.

### 실행 명령

```text
디자인은 실제 알파·모바일 크롭, 영상은 120프레임·루프 경계, 개발은 입력 오류·재시도 계약을 각각 인수 기준으로 작성하라.
```

### 설정·계약

조건·대상·측정 방법·허용 오차·증거를 정한다. 미적 기준은 참조와 비교 포인트를 함께 쓴다.

### 검수

제3자가 같은 파일·환경으로 같은 통과 여부를 판단할 수 있는지 확인.

### 수정 명령

```text
‘자연스럽다’에 머무르지 말고 형태 유지·경계 튐·속도 연속성처럼 관찰 가능한 요소로 나눠라.
```

<a name="x1-03"></a>
## X1-03 · 화면비·리프레이밍

**Aspect Ratio / Reframing** · PDF 144쪽

### 뜻·쓰임

가로와 세로의 비율 및 다른 캔버스에 맞춰 구도를 다시 잡는 작업이다. 가로·세로 광고와 반응형 자산 제작에 쓰인다.

### 혼동 구분

해상도와 다르다. 16:9를 9:16으로 바꾸는 것은 보통 단순 축소가 아니라 크롭·재배치·확장 문제다.

### 실행 명령

```text
가로 히어로를 세로 광고로 리프레이밍하고 제품·제목·CTA의 우선순위를 유지하라. 잘리는 영역과 새로 필요한 배경을 표시하라.
```

### 설정·계약

원본/목표 비율·픽셀 수·안전 영역·확장 허용 범위를 정한다.

### 검수

제품과 글자가 찌그러지지 않고 중요 정보가 목표 크롭에 남는지 확인.

### 수정 명령

```text
비율을 강제로 늘리지 말고 크롭·재배치·배경 확장 중 적합한 방식을 선택하라.
```

<a name="x1-04"></a>
## X1-04 · 납품 명세

**Delivery Specification** · PDF 144쪽

### 뜻·쓰임

파일 형식·크기·색·시간·구조·폴더를 수신 환경의 요구로 정의한 계약이다. AI 생성 결과가 실제 업무에 들어가게 하는 마지막 연결이다.

### 혼동 구분

프롬프트 본문의 ‘4K·SVG·24fps’는 실제 파일 속성을 보장하지 않는다. 생성·후처리·검수 단계의 책임을 나눈다.

### 실행 명령

```text
이미지는 픽셀·프로파일·알파, 영상은 코덱·컨테이너·FPS·오디오, 코드는 런타임·실행법·산출물 위치를 명세표로 제출하라.
```

### 설정·계약

필수 규격·허용 대체·파일 이름·검증 도구·호환 환경을 정한다.

### 검수

파일을 직접 열고 메타데이터와 기능이 명세에 맞는지 확인.

### 수정 명령

```text
스크린샷으로 납품 완료를 판단하지 말고 실제 사용할 파일과 실행 결과를 검수하라.
```

<a name="x1-05"></a>
## X1-05 · 편집 원본·마스터

**Editable Source / Master** · PDF 145쪽

### 뜻·쓰임

편집 가능한 구조·고품질 기준본을 보존한 산출물이다. 파생 크기·번역·수정·재인코딩을 반복할 때 원천으로 사용한다.

### 혼동 구분

검토용 압축본과 다르며 master라는 이름만으로 원본 품질이 보장되지는 않는다. 코드에서는 실행·수정 가능한 프로젝트가 대응한다.

### 실행 명령

```text
레이어 원본·폰트·연결 자산과 고품질 마스터를 정리하고, 평면화·압축된 배포본은 별도 폴더에 두라.
```

### 설정·계약

필요 앱·버전·플러그인·외부 경로·색 설정을 기록한다. 수신자가 사용할 수 있는 대체 형식을 합의한다.

### 검수

원본을 열어 텍스트·색·타이밍을 수정하고 파생본을 다시 생성할 수 있는지 확인.

### 수정 명령

```text
최종 JPG에서 수정하지 말고 원본 구조를 고친 뒤 모든 파생본을 재출력하라.
```

<a name="x1-06"></a>
## X1-06 · 자산 매니페스트

**Asset Manifest** · PDF 145쪽

### 뜻·쓰임

사용·납품한 파일과 역할·경로·버전·속성의 목록이다. 누락 링크·잘못된 버전·의존성 손실을 줄인다.

### 혼동 구분

폴더의 파일명 나열만으로 충분하지 않다. 자산이 어디서 어떻게 쓰이는지와 생성 이력이 필요하다.

### 실행 명령

```text
각 자산에 ID, 파일명, 역할, 크기·시간, 색/알파, 사용 위치, 원본 출처, 버전을 표로 작성하라.
```

### 설정·계약

상대 경로·대소문자·외부 URL·필수/선택·체크섬을 정한다. 실제 비밀값은 기록하지 않는다.

### 검수

목록의 파일이 존재하고 프로젝트 링크가 수신 환경에서 끊기지 않는지 확인.

### 수정 명령

```text
‘최종’ 폴더만 넘기지 말고 각 파일의 용도와 연결 관계를 함께 제공하라.
```

## X1-07 · 버전 관리·변경 기록

**Versioning / Changelog** · PDF 146쪽

### 뜻·쓰임

산출물의 변경 순서와 내용을 식별하는 체계다. 잘못된 시안 사용·리뷰 혼선·호환성 문제를 줄인다.

### 혼동 구분

final_final 같은 이름은 상태·순서를 명확히 전달하지 못한다. SemVer는 공개 API 호환 의미가 있을 때 적용한다.

### 실행 명령

```text
파일에 안정적인 자산 ID와 버전을 사용하고 변경 기록에 바뀐 내용·영향·검수 결과를 적어라. 승인 상태는 별도 필드로 관리하라.
```

### 설정·계약

버전 증가 규칙·기준본·날짜·수정자·파생 관계를 정한다. 되돌릴 수 없는 변경을 표시한다.

### 검수

리뷰 의견이 어느 버전에 대한 것인지 확인되고 오래된 파생본이 섞이지 않는지 확인.

### 수정 명령

```text
기존 파일을 같은 이름으로 조용히 덮기보다 버전과 변경 근거를 연결하라.
```

<a name="x1-08"></a>
## X1-08 · 체크섬

**Checksum / Content Hash** · PDF 146쪽

### 뜻·쓰임

파일 바이트에서 계산한 식별값으로 동일성·전송 손상을 확인하는 수단이다. 큰 자산·빌드 산출물의 원본과 전달본을 비교할 때 쓴다.

### 혼동 구분

해시가 같다는 것은 바이트 동일성이지 내용의 품질·안전성·저작권을 보증하지 않는다. 서명과도 다르다.

### 실행 명령

```text
납품 파일의 SHA-256을 매니페스트에 기록하고 전송 후 동일성을 확인하라. 메타데이터 수정 후에는 해시를 다시 계산하라.
```

### 설정·계약

알고리즘·파일 경로·계산 시점·정규화 여부를 명시한다.

### 검수

전달본과 승인본이 같은 바이트인지, 의도치 않은 변경이 없는지 확인.

### 수정 명령

```text
파일 크기만 비교하지 말고 필요한 경우 실제 해시를 대조하라.
```

## X1-09 · 출처·사용권 기록

**Provenance / Usage Rights** · PDF 147쪽

### 뜻·쓰임

참조·원본·생성·수정 과정과 사용 허가 조건을 기록하는 관리 정보다. 폰트·음악·이미지·코드의 실제 활용 범위를 판단하는 데 필요하다.

### 혼동 구분

AI로 생성했다는 사실만으로 모든 참조·상표·인물·소재 권리가 자동 정리되는 것은 아니다. 불확실한 사항은 확인 대상으로 표시한다.

### 실행 명령

```text
자산별 출처, 라이선스·사용 범위, 필요한 표기, 모델·참조 입력과 변형 이력을 기록하고 확인되지 않은 항목을 구분하라.
```

### 설정·계약

상업 이용·배포·편집·임베딩 등 실제 사용 방식에 맞춰 원문 조건을 확인한다. 타인의 비공개 정보를 매니페스트에 노출하지 않는다.

### 검수

납품 목적에 필요한 권리 확인이 기록되고 출처가 없는 외부 자산이 섞이지 않는지 확인.

### 수정 명령

```text
‘무료’라는 설명만 믿지 말고 정확한 자산·버전의 조건과 사용 범위를 확인하라.
```

<a name="x1-10"></a>
## X1-10 · 프리플라이트

**Preflight / Pre-delivery Check** · PDF 147쪽

### 뜻·쓰임

납품 전에 파일 구조·규격·의존성·오류를 확인하는 최종 검사다. 인쇄의 폰트·색·재단부터 영상·코드의 실행 조건까지 확장해 사용할 수 있다.

### 혼동 구분

미리보기에서 예뻐 보이는 것만으로 완료되지 않는다. 검토 파일과 실제 전달 파일이 동일한지 확인해야 한다.

### 실행 명령

```text
PDF의 글꼴·페이지·링크, 영상의 코덱·프레임·음량, 코드의 실행·환경을 각 명세에 따라 검사하고 결과표를 제출하라.
```

### 설정·계약

필수 통과 항목·경고·미검증·예외 승인 근거를 분리한다. 불필요한 형식 인증을 주장하지 않는다.

### 검수

최종 파일 버전에 대해 검사가 수행되었고 수정 후 이전 결과를 재사용하지 않았는지 확인.

### 수정 명령

```text
내보내기 후 파일을 다시 열어 실제 전달본을 검수하라.
```
